Raw material, Cloudflare, 18 November 2025, all times UTC. 11:05 a permissions change was deployed on a ClickHouse database cluster so users could see metadata for underlying tables in the r0 database, not just the default database. The Bot Management feature file is regenerated every five minutes by a query over system.columns that filters on table name but not on database name. After 11:05 that query started returning duplicate rows, more than doubling the number of feature rows written into the generated file. The proxy's bots module preallocates memory for that file and will not load more than 200 features from it; the bot-scoring model itself uses about 60 features at runtime, so the limit had never been approached before. The doubled file carried more than 200 features. Crossing the limit triggered an unwrap on an Err in the FL2 Rust path: thread fl2_worker_thread panicked, returning HTTP 5xx. Rollout was gradual across ClickHouse nodes, so good and bad files alternated every five minutes and the network recovered then failed repeatedly. FL2 customers saw 5xx; FL1 customers saw no errors but all traffic scored bot=0, producing false positives for anyone blocking on bot score. Cloudflare's independently hosted status page went down coincidentally; responders suspected an Aisuru-style DDoS. 11:28 impact starts, 11:31 first automated detection, 11:35 incident call, 13:05 Workers KV and Access bypass, 14:24 propagation stopped, 14:30 core traffic normal, 17:06 all clear. Worst outage since 2019. Write the root-cause section of the public postmortem for customers and outside engineers.
