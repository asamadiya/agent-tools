Raw material for the section of the node-swap KEP that specifies how a container's swap limit is computed. Swap access is granted only to Burstable QoS pods, and the values are computed automatically rather than entered by the user. Two steps. First, take the container's memory request divided by the node's total physical memory; call that ContainerMemoryProportion. If a container has memory requests equal to memory limits, its proportion is defined as zero, so its swap limit works out to zero. Second, multiply that proportion by TotalPodsSwapAvailable, which is the total swap on the system minus the system-reserved memory — the residue that keeps swap available to system-critical daemons, since the kernel has no memory.swap.min to reserve with. Worked example: a Burstable pod with container A requesting 20 GB and container B requesting 10 GB, on a node with 40 GB of physical memory and 40 GB of swap, with system-reserved memory configured at 2 GB. Proportions come out at 0.5 and 0.25; TotalPodsSwapAvailable is 38 GB; A gets a 19 GB swap limit and B gets 9.5 GB. The scheme ties each container's share of swap to its memory request and rescales it against whatever swap the system actually has.
