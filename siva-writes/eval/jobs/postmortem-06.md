Raw material, Cloudflare, 12 September 2025, all times UTC. The Tenant Service API went down and took much of the public API and the Cloudflare Dashboard with it, because Tenant Service sits in the API request authorization path; when authorization cannot be evaluated, requests return 5xx. Trigger: a dashboard bug. API calls were driven by a React useEffect whose dependency array contained an object recreated on every state or prop change, so React treated it as always new and the call to /organizations fired many times per render, with retries on failure. Timeline: 16:32 the buggy dashboard version ships; 17:50 a new Tenant API Service version deploys; 17:57 Tenant Service is overwhelmed and dashboard availability starts dropping; 18:17 after adding resources the API reaches 98% availability but the dashboard does not recover; 18:58 an attempt to remove erroring codepaths ships and makes API impact worse; 19:01 a temporary rate-limiting rule is published; 19:12 the changes are reverted and dashboard availability returns to 100%. Tenant Service is a Go process on Kubernetes in a subset of datacenters; responders added pods and a global rate limit. Restarting it caused every dashboard to re-authenticate at once, a thundering herd amplified by the dashboard loop. Control plane and data plane are strictly separated, so network services were unaffected and most users noticed nothing unless making config changes. Argo Rollouts, which auto-rolls-back on detected errors, had not yet been adopted for Tenant Service and would have caught the second bad update. Responders could not distinguish retries from new requests in telemetry. Write the public postmortem for dashboard and API users.
