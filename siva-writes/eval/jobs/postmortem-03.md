Raw material, Cloudflare, 5 December 2025, all times UTC. Impact 08:47 to 09:12, about 25 minutes. Roughly 28% of all HTTP traffic Cloudflare serves was affected. Not an attack. The WAF buffers HTTP request bodies in memory for inspection; the buffer had been 128KB. To cover customers against CVE-2025-55182, a critical React Server Components vulnerability, Cloudflare began raising the buffer to 1MB, the Next.js default limit. That first change went out through the gradual deployment system. During rollout an internal WAF testing tool turned out not to support the larger buffer, so a second change disabled that tool. The tool had no effect on customer traffic, but the disable was made through the global configuration system, which does no staged rollout and reaches the entire fleet within seconds. The disable was implemented as a killswitch in the rulesets system. A rule's action can be block, log, skip, or execute, where execute triggers evaluation of a sub-ruleset. A killswitch had never before been applied to a rule with action execute. The skip was honoured, but result-processing code still dereferenced rule_result.execute, which did not exist, producing a Lua nil index error at init.lua line 314 in the FL1 proxy and HTTP 500s. The bug had sat undetected for years; the Rust reimplementation in FL2 does not have it. Affected: customers on FL1 with the Cloudflare Managed Ruleset deployed, all requests 500ing except some test endpoints such as /cdn-cgi/trace. China network traffic unaffected. 08:50 declared by automated alerts, 09:11 revert, 09:12 propagation complete. Write the public incident writeup for customers who saw 500s.
