Raw material for the risks section of the node-swap KEP, covering four risks and what was done about each. Resource exhaustion: earlier releases offered an UnlimitedSwap option for workloads, which let a workload consume all the swap on a node and push the node unhealthy; UnlimitedSwap was dropped from the API in beta2. Security: swap on an unencrypted disk can put critical information, including Kubernetes secrets, onto disk where anyone with disk access can read it; the mitigation is encrypted swap, but handling encryption is a general OS configuration concern outside the kubelet's remit, so the answer is documentation that warns users. Cgroups v1: supporting it was an early goal, but sig-node concluded that swap on cgroup v1 would be very difficult, so the feature is limited to cgroups v2; cgroup v1 is expected to be deprecated eventually, which blunts the inconvenience. Memory-backed volumes: Kubernetes guarantees some volumes never reside on disk — secrets, memory-backed emptyDirs — and the kubelet mounts them as tmpfs on the host. When --fail-swap-on=false, the tmpfs noswap option is used to keep those pages off disk. That option needs kernel 6.4 or newer, though distributions may backport it, so the kubelet uses it when the kernel is at least 6.4, otherwise tries mounting a dummy volume with noswap to detect a backport, and otherwise warns that the option is unsupported.
