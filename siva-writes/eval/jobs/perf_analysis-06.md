Second half of a Netflix case study on a file-processing microservice whose 100-Gbyte S3 uploads took hours while 40-Gbyte ones took minutes. Memory evidence: free -m on the problem instance showed total 64,414 MB, used 15,421, free 349, buff/cache 48,643, available 48,409, swap 0. So a 64-Gbyte memory system with 48 Gbytes sitting in the page cache and only 349 MB free. That plus the file sizes suggested a theory: 100-Gbyte files bust the page cache while 40-Gbyte files fit. Confirmation came from cachestat, an experimental tool written for Ftrace and since ported to bcc/eBPF, which reports page cache statistics. On the 100-Gbyte upload, cachestat showed hit ratios of 74.1%, 9.7%, 6.5%, 12.0%, 34.5%, 7.0%, 11.1% per second, with misses running from 632 up to 23,341, BUFFERS_MB 17 and CACHE_MB about 48,000. Ratios in the upper 90s are what you want to see; this is cache busting, because the 100-Gbyte file does not fit in 48 Gbytes of page cache, so misses turn into disk I/O. Control test on a 32-Gbyte file upload: cachestat showed 100.0% hit ratio with 0 misses across every second sampled (hits 33,424 to 65,158), BUFFERS_MB 41, CACHE_MB about 33,680; free -m showed used 18,421, free 11,218, buff/cache 34,773; iostat showed almost no disk I/O. The smaller file is processed entirely from memory however many passes it takes, without re-reading from disk. Recommended fixes: quickest is a larger-memory instance that fits the 100-Gbyte files; developers can also rework the code with the memory constraint in mind, for example processing parts of the file rather than making multiple passes over the whole thing. Closing context: cachestat was the killer tool but is still experimental, built under the constraints of low overhead and Ftrace function-profiler only. At the LSFMMBPF 2019 keynote in Puerto Rico, with Linux mm kernel engineers present, the argument was made that these statistics are commonly enough needed that they belong in /proc; the engineers pointed out real challenges in providing them properly, and page cache counters are hot-path so adding them is not free.
